# 0.10.0-PLAN.md — bring the codebase in-line with the finalized spec family

Status: working plan (files only). Version target: **0.10.0**, completed **prior to the 1.0.0
(Cosanima) release**, which has its own spec.

## Context

The graph-native spec family was designed, then implemented in the working tree under the
**pre-finalization model**: the full PHASE_01–05 build landed uncommitted on `main` —
4-tier taxonomy + spine, invariant mechanism, assertion/milestone plan lifecycle, the
`future/`-namespace migration, archive/retag removal, docs, and a dogfooded project
(`HANDOVER.md` is its checkpoint). **After** that implementation was built, the spec family was
**finalized** with one structural change: the **`Future` node is removed** in favour of
**planned Implementation nodes** (`Module`/`File`/`Struct`/`Function` marked `planned`,
plan-writer-authored, scanner-replaced), with the plan as the pre-build bridge and a
planned-node **realization** apply gate. The specs were reconciled to that model in commit
`169959d`; the code has not caught up yet. `REVIEW.md` additionally carries a set of open
(`[ ]`) divergences against the final model.

This plan reorients 0.10.0 to **bring the current codebase state in-line with the new specs**:
land the existing implementation as a green checkpoint, reconcile the `Future` machinery to
planned Implementation nodes, close every open REVIEW.md divergence, re-run docs/agents/dogfood
under the finalized model, and cut the release.

## Objective

By 0.10.0, the shipped apg matches the finalized spec family exactly:

- **Planned Implementation nodes**, not `Future` — plan-writer-authored, marked `planned`,
  replaced by the scanner when the code exists; the **plan is the bridge** to the Solution tier
  pre-build, the direct `ImplementedBy` spine post-build.
- **No open divergences** — every `[ ]` item in `REVIEW.md` is implemented or explicitly
  reconciled.
- **Docs, agents, and the dogfooded E2E** describe and exercise the finalized model.
- **Release readiness** — version pins at 0.10.0 (already in the tree), release records
  re-pointed, handoff queued (tag/push/bottles human-owned).

## Reference specs

- **GraphModel-SPEC.md** — the 4-tier graph; **planned nodes** (tier-4 `status: planned`,
  scanner-replaced); two-phase spine (plan as bridge pre-build, `ImplementedBy` post-build);
  branch-as-change-set versioning; no archive.
- **Invariants-SPEC.md** — `Invariant` node, `GuardedBy`/`Checks`, emergent lifecycle.
- **SpecCreation-SPEC.md** — tiers 1–3 only; spec-writer never authors planned code.
- **PlanCreation-SPEC.md** — plan-writer authors the planned Implementation nodes + the plan;
  `Builds(Task → planned node)`.
- **PlanExecution-SPEC.md** — assertion-only `plan done`, milestone-only `plan complete`,
  branch scans replace planned nodes, human gate.
- **PlanCompletion-SPEC.md** — apply-the-diff; coherence gate = every planned node realized.
- Inputs: **HANDOVER.md** (what the working tree implements), **REVIEW.md** (open divergences).

## Strategy

Oldschool, additive-first, each phase independently mergeable and gated green (`cargo test`):

1. **Land the baseline** — commit the working-tree implementation as-is (green checkpoint
   under the pre-finalization model; gives a rollback point before the surgery).
2. **Reconcile the one structural change** — `Future` → planned Implementation nodes
   (schema/merge/ingest, CLI, data migration, apply gate).
3. **Close the open divergences** — every `[ ]` item in REVIEW.md.
4. **Re-align docs + agents + dogfood** — everything describes/exercises the finalized model.
5. **Cut 0.10.0** — release records re-pointed; handoff to the human.
